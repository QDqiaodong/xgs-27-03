# xgs-27 短视频投稿脚本多评委加权自动分级评审系统

## 项目简介

短视频投稿脚本多评委加权自动分级评审系统，包含 Spring Boot 后端、Vue/Vite 前端、MySQL 与 Redis。

## 脚本双盲脱敏视图

系统内置脚本级双盲脱敏链路（`identity_group` / `identity_clue` / `desensitization_audit`，接口 `/api/scripts/**`、`/api/desensitization/audits`）：

- **原稿与脱敏视图分离**：管理员录入的原稿完整保留作者、来源机构、联系方式、正文与附件说明；评委与普通查看员从任何入口（列表、详情、回避、分配、统计、打印）拿到的都只是从原稿派生的脱敏视图，响应结构本身不含原始作者/来源/联系方式字段，“只隐藏界面而详情响应携带原文”不成立。
- **同一套规则覆盖全部位置**：元数据（作者/来源机构/联系方式）与自由文本（标题、正文、附件说明）统一识别姓名、电话、邮箱、社交平台标识、机构全称；电话/邮箱/链接按模式整体替换，不会只遮一半。
- **稳定代号且不可横向关联**：同一脚本内同一身份的所有出现（含两字名别名，如“刘雨桐/雨桐”）共用同一代号，代号形如 `【作者A·7K2QXQ】`；字母在脚本内稳定，盐值每脚本随机生成，同一投稿人在不同脚本得到完全不同的代号，评委无法跨脚本关联；相似姓名按归一化原文精确归并，不会因同姓/形近被合并。
- **剧情人物保留、模糊线索待核对**：带剧情语境的姓名（剧中人物/角色/饰演/顾客/室友…）识别为剧情人物并保留原文，脚本可读性不被破坏；无法确定身份的姓名标记为 `【待核对X·盐】`，评委侧在管理员核对前看到的始终是更保守的隐藏结果。
- **管理员三分区核对**：`脚本详情 → 代号映射核对` 明确区分①原始内容 ②识别出的线索（字段、原文片段、识别依据、代号、状态）③脱敏结果；管理员可把待核对分组确认为“投稿身份”（代号替换）或“剧情人物”（保留原文），核对只调整脱敏视图与映射，不改写原稿；原稿更新后自动重新识别，已核对结论在身份仍出现时沿用。
- **受控原稿与审计**：`受控查看原稿`、`代号映射核对`、每次身份核对均写入 `desensitization_audit`（谁、何时、IP、动作、详情），管理员可在“脱敏审计”页按脚本追溯；评委/查看员调用受控入口、脚本写操作均在 HTTP 层与服务层双重返回 403。
- **打印与下载**：详情页“打印脱敏视图”在打印样式中隐藏侧栏、按钮与管理员对话框，打印结果只包含已渲染的脱敏内容，打印预览无法带出原稿。
- 后端集成测试 `DesensitizationIntegrationTest`（H2，10 项）覆盖元数据与正文线索识别、同身份稳定替换与别名归并、相似姓名不合并、跨脚本代号不可关联、剧情人物保留、模糊线索保守隐藏与管理员核对、原稿/映射/审计三分区、评委与查看员全入口（含直接访问详情地址、越权受控入口、删除）拿不到原文、跨出口标题脱敏、原稿更新后重新识别。

## 评委利益冲突回避与替补接管

系统内置完整的评委回避链路（`/api/recusals/**`）：

- **申报**：评委在已分配脚本上可申报与作者 / 来源机构 / 题材（及其他）的利益关系，必须填写回避类型、说明与可核验依据；管理员可代评委申报。
- **可见范围**：普通查看员与非申报评委只能看到回避状态；敏感说明、依据、补充材料、审批理由仅申报本人与管理员可见。
- **审批**：管理员可批准、驳回、要求补充材料，每次处理均记录操作者、前后状态与理由（处理轨迹可审计）；管理员不能审批由自己代为提交的申请。同一申请被并发处理时通过行锁 + 乐观锁保证只有一个最终决定。
- **未决期间**：脚本仍可查看，但该评委不能提交新评分。
- **批准**：立即终止其分配（RECUSED），历史评分不删除而是标记无效并保留原文，从总分、极端分识别与等级计算中排除；已分级脚本撤销旧等级进入“待补评”。管理员再指定一名未参与该脚本、状态正常且专业方向匹配的替补评委接管（`uk_replaces_assignment` 保证不会重复创建替补分配）；替补评委仅看到接管后的任务，不继承原评委的评语草稿或敏感回避说明。
- **驳回**：恢复原分配状态与原评分有效性。
- **重新分级**：替补评分进入、有效评分重新达到 2 份后才能再次分级；分级事务与回避批准/替补打分共用同一把脚本行锁，最终等级只使用当时有效的评分，刷新或重新登录后状态一致。
- 后端集成测试 `RecusalIntegrationTest`（H2，13 项）覆盖申报、补充、审批、并发审批、替补接管、评分失效与恢复、事后回避撤销等级、重新分级与审计轨迹，以及管理员/评委/查看员三类角色的可见范围。

## 启动命令

```sh
./start.sh
```

或：

```sh
docker compose up -d --build
```

## 单独构建验证

- 后端: `cd backend && mvn compile -q`
- 前端: `cd frontend && npm ci && npm run build`

## Docker 交付说明

前后端 Dockerfile 均包含依赖缓存层：后端先复制 `pom.xml/settings.xml` 下载 Maven 依赖，再复制 `src` 编译；前端先复制 `package.json/package-lock.json` 执行 `npm ci`，再复制源码构建。端口固定写入 `.env`，Compose 端口均绑定 `127.0.0.1`。
